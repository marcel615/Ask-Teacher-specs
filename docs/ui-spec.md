# UI 명세

## 1. 개요

### 목적

Ask Teacher는 사용자가 질문을 작성하고 다른 사용자의 질문을 조회할 수 있는 Q&A 서비스다.

본 문서는 웹 화면의 구성, 사용자 동작, 화면 전환 및 공통 UI 처리 기준을 정의한다.

### 관련 공식 명세

- [공통 요구사항](requirements.md)
- [API 및 인증 명세](api-spec.md)
- [ERD](erd.md)

API 요청·응답 구조, 데이터 검증 및 인증·인가 규칙은 각 공식 명세를 따른다.

본 문서는 React 컴포넌트, 상태 관리 라이브러리, API 함수명 등 구체적인 구현 방식을 규정하지 않는다.

기능의 구현 진행 상태는 GitHub Issue 및 PR에서 관리한다.

---

## 2. 사용자 유형

### 비로그인 사용자

- 회원가입 및 로그인 화면에 접근할 수 있다.
- 게시글 목록과 상세 내용을 조회할 수 있다.
- 카테고리와 게시글별 댓글을 조회할 수 있다.

### 로그인 사용자

- 비로그인 사용자의 조회 기능을 이용할 수 있다.
- 질문 게시글을 작성할 수 있다.
- 본인이 작성한 게시글을 수정하거나 삭제할 수 있다.
- 댓글 작성·수정·삭제 및 좋아요 등 인증이 필요한 기능을 이용할 수 있다.

### 관리자

- 현재 별도의 관리자 전용 화면은 정의하지 않는다.

## 3. 화면 및 라우팅

| 화면 | 경로 | 설명 |
|---|---|---|
| 게시글 목록 | `/posts` | 질문 목록 조회 |
| 게시글 작성 | `/posts/create` | 질문 작성 |
| 게시글 상세 | `/posts/:postId` | 질문 상세 조회 |
| 게시글 수정 | `/posts/:postId/edit` | 기존 질문 수정 |
| 로그인 | `/login` | 로그인 |
| 회원가입 | `/signup` | 계정 생성 |

위 경로는 기존 Frontend 요구사항에서 정의한 화면 경로를 기준으로 한다.

신규 기능의 화면과 경로는 관련 Parent Issue에서 구체화한 후 본 문서에 반영한다.

## 4. 공통 레이아웃 및 UI 동작

### 헤더 및 이동

- 서비스명과 주요 탐색 메뉴를 제공한다.
- 서비스명 클릭 시 게시글 목록 또는 홈 화면으로 이동한다.
- 로그인 및 회원가입 화면으로 이동할 수 있는 수단을 제공한다.
- 현재 사용자 인증 상태에 따른 메뉴 표시 정책은 별도 기능 결정에 따른다.

### 공통 상태 처리

- 데이터를 불러오는 동안 로딩 상태를 표시한다.
- 조회 결과가 없는 경우 적절한 빈 데이터 메시지를 표시한다.
- 요청 실패 시 사용자가 이해할 수 있는 오류 메시지를 표시한다.
- 작성·수정·삭제 등 중복 제출이 문제가 되는 작업은 요청 중 반복 실행을 방지한다.
- 입력값 검증 실패 시 서버 요청 전에 사용자에게 해당 문제를 안내한다.
- 서버 오류 발생 시 작성 중인 입력값은 가능한 한 유지한다.

## 5. 게시글 목록 화면

**경로:** `/posts`

### 화면 구성

- 게시글 목록
- 게시글 제목
- 작성자 닉네임
- 생성일
- 새 글 표시
- 새 글 작성 화면으로 이동하는 버튼

### 사용자 동작

- 화면 진입 시 게시글 목록을 조회한다.
- 게시글 제목을 클릭하면 해당 게시글 상세 화면으로 이동한다.
- 새 글 작성 버튼을 클릭하면 게시글 작성 화면으로 이동한다.
- 새 글 여부가 참인 게시글에는 `new` 표시를 노출한다.
- 게시글이 없다면 "게시글이 없습니다."라는 메시지를 표시한다.
- 데이터 조회 중 로딩 상태를 표시하고 실패 시 오류 메시지를 표시한다.

### 향후 확장

- 키워드 검색
- 카테고리 필터
- 페이지 이동
- 좋아요 수 표시

세부 동작은 관련 기능 Issue에서 구체화한다.

---

## 6. 게시글 작성 화면

**경로:** `/posts/create`

### 화면 구성

- 카테고리 선택
- 제목 입력
- 내용 입력
- 작성 버튼

### 사용자 동작

- 화면 진입 시 선택 가능한 카테고리를 조회한다.
- 사용자는 카테고리, 제목, 내용을 입력한다.
- 제목은 필수이며 최대 100자다.
- 내용은 필수이며 최대 5000자다.
- 제목과 내용은 공백만 입력할 수 없다.
- 입력값 검증에 실패하면 요청을 보내지 않고 경고 메시지를 표시한다.
- 작성 중에는 중복 제출을 방지한다.
- 작성 성공 시 성공 안내 후 `/posts`로 이동한다.
- 작성 실패 시 오류 메시지를 표시한다.

### 향후 확장

- 이미지 및 PDF 첨부파일 선택·업로드

파일 형식과 용량 제한은 API 명세를 따른다.

## 7. 게시글 상세 화면

**경로:** `/posts/:postId`

### 화면 구성

- 제목
- 내용
- 작성자 닉네임
- 카테고리
- 생성일
- 수정 화면 이동 버튼
- 삭제 버튼

### 사용자 동작

- URL의 게시글 ID에 해당하는 정보를 조회한다.
- 존재하지 않거나 조회할 수 없는 게시글은 오류 상태를 표시한다.
- 수정 버튼을 클릭하면 게시글 수정 화면으로 이동한다.
- 삭제 버튼을 클릭하면 삭제 확인 절차를 시작한다.

### 향후 확장

- 좋아요 수 및 현재 사용자의 좋아요 상태
- 첨부파일 목록
- 댓글 목록 및 댓글 작성 UI

수정·삭제 버튼의 표시 조건은 인증 및 작성자 권한 정책과 일치해야 하며, 구체적인 표시 방식은 관련 Issue에서 결정한다.

---

## 8. 게시글 수정 화면

**경로:** `/posts/:postId/edit`

### 화면 구성

- 기존 카테고리 선택값
- 기존 제목
- 기존 내용
- 수정 버튼

### 사용자 동작

- 화면 진입 시 기존 게시글 정보와 카테고리 목록을 조회한다.
- 기존 입력값을 수정 가능한 상태로 표시한다.
- 제목과 내용은 작성 화면과 동일한 입력 검증 규칙을 따른다.
- 검증에 실패하면 수정 요청을 보내지 않는다.
- 수정 요청 중에는 중복 제출을 방지한다.
- 수정 성공 시 `/posts/:postId` 상세 화면으로 이동한다.
- 수정 실패 시 오류 메시지를 표시하고 입력값을 유지한다.

---

## 9. 게시글 삭제 기능

**사용 화면:** 게시글 상세

### 사용자 동작

- 삭제 버튼을 클릭하면 삭제 확인 대화상자를 표시한다.
- 확인하면 삭제 요청을 실행한다.
- 취소하면 요청 없이 기존 화면에 머문다.
- 삭제 요청 중에는 중복 실행을 방지한다.
- 삭제 성공 시 `/posts`로 이동한다.
- 삭제 실패 시 오류 메시지를 표시한다.

---

## 10. 회원가입 화면

**경로:** `/signup`

### 화면 구성

- 이메일 입력
- 비밀번호 입력
- 닉네임 입력
- 회원가입 버튼

### 사용자 동작

- 이메일 형식과 필수 입력 여부를 검증한다.
- 비밀번호는 최소 8자여야 한다.
- 닉네임은 2자 이상 20자 이하여야 한다.
- 검증 실패 시 요청을 보내지 않는다.
- 회원가입 요청 중에는 중복 제출을 방지한다.
- 회원가입 실패 시 화면을 유지하고 오류를 안내한다.
- 회원가입 성공 시 게시글 목록 화면으로 이동한다.

최종 입력 검증과 중복 확인 규칙은 공식 API 명세를 따른다.

---

## 11. 로그인 화면

**경로:** `/login`

### 화면 구성

- 이메일 입력
- 비밀번호 입력
- 로그인 버튼

### 사용자 동작

- 이메일 형식 및 필수 입력 여부를 검증한다.
- 로그인 버튼 클릭 시 인증 요청을 실행한다.
- 로그인 실패 시 오류 메시지를 표시한다.
- 로그인 성공 시 게시글 목록 화면으로 이동한다.

### 인증 연계

- Access Token, Refresh Token, CSRF 및 재발급 정책은 공식 API 명세를 따른다.
- 인증 상태를 사용하는 화면과 보호된 기능은 서버의 인증·인가 규칙과 일치해야 한다.
- 자동 재발급, 탭 간 인증 상태 동기화 및 인증 만료 시 화면 처리의 구체적인 UX는 관련 Issue에서 결정한다.

다음 항목은 개별 기능 Issue를 통해 세부 화면 요구사항을 확정한다.

- 댓글 작성·수정·삭제
- 게시글 및 댓글 좋아요
- 검색·필터·페이징
- 첨부파일 업로드 및 표시
- 로그인 상태에 따른 메뉴·버튼·화면 접근 제어
- 질문의 새 댓글 알림
- 기타 승인된 공통 기능

해당 기능의 화면·경로·사용자 동작이 확정되면 본 문서를 갱신한다.

## 13. 명세 관리 원칙

1. 사용자에게 제공할 화면과 동작은 이 문서에서 정의한다.
2. API·인증·데이터 구조는 Specs의 해당 공식 명세를 따른다.
3. 개별 기능의 미결정 사항과 승인 이력은 Parent Issue에서 관리한다.
4. React 내부 구현 설계와 작업 이력은 Frontend Issue 및 개발 문서에서 관리한다.
5. 문서 변경이 필요한 경우 관련 영향 범위를 검토하고 승인된 내용만 반영한다.
6. 기능 완료 여부는 이 문서의 체크박스가 아닌 Issue·PR·검증 결과로 판단한다.
